# 🚨 SOC L1 Alert Triage

## 🎯 Objective

This room introduces the concept of SOC alerts, how alerts are generated, their lifecycle, and how a Tier 1 SOC Analyst performs alert triage to identify and respond to potential security threats.

---

## 📝 Summary

A Security Operations Center (SOC) receives millions of security events every day. Instead of manually reviewing every log, security tools such as SIEM and EDR generate alerts whenever suspicious activity matches predefined detection rules.

The primary responsibility of a SOC Level 1 Analyst is to review, prioritize, investigate, classify, and escalate alerts when necessary. Alert triage helps detect real threats quickly while reducing time spent on false positives.

---

## ⭐ Key Takeaways

- Alerts are generated from suspicious events detected by security tools.
- SIEM, EDR, NDR, SOAR, and ITSM platforms help manage alerts.
- SOC L1 Analysts perform alert triage.
- Alert prioritization is based on status, severity, and time.
- Every alert must be investigated before assigning a verdict.
- Proper documentation and escalation are critical.

---

# 🔄 From Events to Alerts

## Alert Generation Process

```text
Event Occurs
      ↓
System Generates Logs
      ↓
Logs Sent to SIEM / EDR
      ↓
Detection Rule Matches Activity
      ↓
Security Alert Created
      ↓
SOC Analyst Reviews Alert
```

### Example Events

- User Login
- Process Execution
- File Download
- PowerShell Execution
- Network Connection
- Firewall Event

Instead of reviewing millions of logs manually, analysts investigate only suspicious alerts generated by detection rules.

# 🚀 Alert Prioritization

SOC analysts should investigate alerts in the following order.

### 1️⃣ Filter Alerts

- Ignore alerts already assigned.
- Focus only on new and unresolved alerts.

### 2️⃣ Sort by Severity

```text
Critical
   ↓
High
   ↓
Medium
   ↓
Low
```

### 3️⃣ Sort by Time

- Investigate the oldest alerts first.
- Older attacks may already be progressing through the attack lifecycle.

# 🔍 SOC L1 Alert Triage Workflow

```text
Assign Alert
      ↓
Set Status → In Progress
      ↓
Review Alert Details
      ↓
Investigate Evidence
      ↓
Determine Verdict
      ↓
Document Findings
      ↓
Escalate if Necessary
      ↓
Close Alert
```

---

# 🧩 Investigation Checklist

Before deciding the verdict:

- Identify the affected user or system.
- Understand the suspicious activity.
- Review surrounding events.
- Search for additional Indicators of Compromise (IOCs).
- Verify findings using Threat Intelligence.
- Decide whether the activity is malicious or benign.

---

# ✅ Final Actions

After completing the investigation:

- Determine whether the alert is:
  - 🔴 True Positive
  - 🟢 False Positive
- Write detailed investigation notes.
- Explain the reasoning behind the verdict.
- Escalate to L2 if required.
- Close the alert.

---

# 💡 SOC L1 Best Practices

- Only investigate alerts assigned to you.
- Prioritize Critical and High severity alerts.
- Never assume an alert is malicious without evidence.
- Always document your findings.
- Escalate when additional expertise is required.
- Follow investigation playbooks whenever available.

---

# 📝 SOC L1 Investigation Questions

Whenever you receive an alert, ask yourself:

- Who is affected?
- What happened?
- When did it happen?
- Where did it happen?
- Why was the alert triggered?
- Is there supporting evidence?
- Is it a True Positive or False Positive?
- Does it need escalation?
